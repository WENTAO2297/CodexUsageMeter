# Weekly 历史粗估

连续观测预测仍优先；只有其缺少证据时才启用后备。Session、流量和菜单行为不变。面板右列显示预计余量范围或可用天数与短结论，颜色中性。标题已经包含“预计”，所以不重复约等号，不显示估算依据小字；历史粗估的依据仍在内部模型及辅助功能中。原有两句悬停提醒不加长。

典型情景预测周额度会在重置前耗尽时，右列改为“预计还能用”与 `3.2天`，不足一天显示 `<1天`；只保留“可能耗尽”短结论，不再只显示重置时 `0%`。可用天数为当前余量 ÷ 同一典型情景的日均消耗，最多一位小数、向下取整；它假设保持该消耗速度，不是精确耗尽时间。仅较高情景接近耗尽（吃紧）不切换；Session短期估计、已耗尽、过期/未知数据仍沿用原有状态。不新增读数或模型调用，回测的消耗模型不变。

## 数据与计算

- 内嵌 `TokenHistoryReader` 只读当前 `CODEX_HOME`（默认 `~/.codex`）的 sessions / archived_sessions。按 session 元数据核对当前账号，筛选 GPT 执行的数字 token 事件及 `limit_id=codex`、10080 分钟的官方额度快照；不依赖 primary/secondary 位置。
- 基于累计输入、缓存输入、输出的增量计数，首事件只计最后一次调用，避免继承的整段历史重复算入。按执行 turn 与累计计数全局去重；内部自动审核调用排除。推理输出不再次叠加到输出，缓存输入不再叠加到总输入。重复 token 事件仍可更新额度快照，但不能增加 token 总数。
- 最近21天数据汇总成UTC日及最多240个数字锚点。同一六小时段保留最后锚点，但任何重置、补额或套餐边界保留独立分区；重置时间允许10分钟协议抖动，小幅并发快照倒退不当成补额。不会分配睡眠缺口中的消耗到每小时，也不补零。
- 校准只用当前套餐开始后的非重叠6–30小时区间；不跨分区。有效下降至少2个百分点、最多80个百分点且至少10000 token，至少3段。模型构成L1距离≤0.6、缓存占比差≤0.2、输出占比差≤0.1是保守工程门槛，不是官方计费权重。
- 用实际额度下降 / 本机 token 消耗形成个人经验比例；不使用API价格或固定token→百分比换算。比例P10/P90分别拓宽25%，过度不一致（上/下比超过10）弃权。这些范围是情景，不是置信区间。
- 日消耗取最近2–7个有额度锚点前后支持的完整UTC日，排除套餐变更当日，使用构成相近的历史日；未来假设维持相近使用习惯。P25/P50/P90日token配合校准，按接口实际剩余期限计算低/典型/高消耗与预计余量范围。
- 粗估只在最新真实额度仍新鲜（180秒）且历史仍有效（6小时）、当前账号/套餐和周期匹配时显示。重置变化、补额、换账号、额度失败、不明身份、未知期限、无足够匹配证据时不盲目预测；原有预算仍单独显示。

## 后台与隐私

扫描最多每6小时一次；周期/套餐变化可提前重读，但至少间隔10分钟。独立NSTask及临时0.25秒完成计时器，不扫描UI主线程；本机数据不发送外部服务、不调用模型，不新增额度网络轮询。扫描有25秒、1500文件、8GiB、150000数字事件上限；超限/读取错误明确失败，不把部分扫描当完整记录。运行App无需Node/Python。

固定本应用私有缓存 `token-history.json` 原子写入，目录0700 / 文件0600，48KB上限。只含账号标识、模型/套餐、日级数字及额度锚点；无执行标识、任务名、路径、原始日志、提示、工具正文或认证凭据。原生程序写缓存只返回 `ok`，避免主进程等待大stdout而发生管道阻塞；测试模式仅在内存输出聚合数据。

## 验证与回测

`zsh verify.sh` 包含纯算法、后台生命周期和真实原生读取器的合成夹具验证：重复/分叉、推理和缓存不重复计算、周窗口位置、模型/缓存构成差异、账号和套餐变化、重置、失败/超时、迟到响应、限频、历史缓存校验，以及中英文本地化、原菜单行为与排版。夹具不访问真实账号或控制任务/VPN。

显式只读真实回测：

```sh
node Tests/token-backtest.cjs --live
```

每个UTC日最多一个预测时点。每次重新用原生读取器按该时点截断，不使用未来token、额度或不完整日训练。随后约24小时的额度消耗作为评分真值；碰到重置/补额、套餐变化或缺少真值则不评分。它验证的是到重置预测中的日消耗分量，并非已证明整周的预测准确率。只打印匿名汇总，不把真实记录写进项目。

2026-10-14最终代码只读真实回测：8个时点，2个可评分、5个因训练证据不足弃权、1个因重置或缺少真值不可评分；平均绝对误差1.6个百分点，两个实际消耗都在粗估情景范围内。完整周重置评估0个。样本很少，**不能据此声称高准确率或95%覆盖率**，也未证明优于旧方案。后续更多周期才能校准门槛和范围。真实记录会继续增长，重新运行的结果可能变化。

本机以外的设备/云端消耗、未记录调用、同套餐隐含容量变化和突发高强度任务都可能造成误差。官方快照反映账号总消耗，本机token并不一定覆盖全部。粗估允许短历史外推到实际期限，内部始终保留历史粗估身份且不使用绿色保证；面板按用户要求只显示预计数值与结论。证据不足时仍会弃权，不为了隐藏“数据不足”而制造数字。
